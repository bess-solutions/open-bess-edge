# Flower FL framework moved to requirements-federated.txt (optional install).
# flwr<=1.32.1 hard-pins cryptography<47.0.0 (see its own METADATA:
# "Requires-Dist: cryptography>=46.0.7,<47.0.0"), which directly conflicts
# with the cryptography>=48.0.1 pin below (GHSA-537c-gmf6-5ccf fix). A single
# requirements.txt cannot satisfy both — `pip install -r requirements.txt`
# fails outright (ResolutionImpossible) if flwr stays here. Since federated
# learning (src/interfaces/fl_client.py, fl_server.py, src/core/fl_coordinator.py)
# is not on the safety-critical dispatch/Modbus path, it's split into its own
# optional file so the core gateway always installs clean and patched.
# See requirements-federated.txt for install instructions and the accepted
# risk this carries until Flower relaxes its own pin upstream.
